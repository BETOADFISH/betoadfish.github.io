# 页面访问与题库使用统计

管理员入口：<https://bill-biology-admin.betoadfish.workers.dev/admin>。沿用现有 GitHub 管理员登录，公开网站不能读取统计接口。

## 先看什么

每周先看页面访问分布和题库的“已载入 / 进入”比例。某个题库的进入会话增加，而载入比例下降时，先排查资源与网络。再看“成功导出 / 已载入”，结合预览、筛选、随机组卷和导出结果，判断用户是否顺利完成选题。

上线前没有这套访问事件，不能补出历史访问量。先积累实际基线，不预设转化率目标。统计服务在中国大陆可能被拦截，即使题库正常打开，事件也可能未送达；这套数据只能描述收到事件的使用情况。

## 指标与分母

| 指标 | 计算方式 | 可以帮助判断 | 使用限制 |
| --- | --- | --- | --- |
| 页面访问 | `page_view` 的条数 | 哪些页面经常被打开 | 刷新和重新进入会重复计算；不等于人数 |
| 临时会话 | 时间范围内有 `page_view` 的不同 `session_id` 数 | 估计使用规模 | 标签页随机编号，不识别个人；不能算回访率 |
| 已载入 / 进入 | 同一题库同时收到 `bank_open` 和 `bank_loaded` 的会话数 ÷ 收到 `bank_open` 的会话数 | 判断题库载入是否中断 | 同一会话重试成功可计为已载入；缺失上报会影响结果 |
| 成功导出 / 已载入 | 同一题库收到进入、载入、开始导出和成功结果的会话数 ÷ 已载入会话数 | 判断已载入会话中有多少生成了 PDF | 是步骤覆盖比例，未验证严格事件顺序；不代表文件保存成功 |
| 载入错误会话 | 同一题库收到进入和 `bank_error` 的会话数 | 找到需要排查的题库 | 同一会话可同时出现错误和重试成功 |
| 已收到结果中的导出成功率 | `export_success` ÷ (`export_success` + `export_error`) | 判断已收到结果的生成质量 | 不把未收到结果当成失败，不能替代完整完成率 |
| 页面可见时长 | `page_active.duration_ms` 之和 | 比较页面在前台停留的量级 | 不等于阅读或做题时间；休眠、关闭、拦截会漏计 |

预览、筛选、随机组卷、开始导出都在同一题库的已载入会话内去重。不同题库分别计数。窗口宽度不推断设备型号；≤767px 为窄屏，其余为宽屏。中英文路径合并为同一个页面类别，同时保留语言字段。

时间范围为滚动 7、30 或 90 天，按北京时间分组，首尾日可能不完整。每日去重会话之和不能当成整段时间的去重会话数。分母为零时显示“无分母”。仪表盘显示最近事件时间，并支持导出当次汇总 CSV。

## 事件边界

- `page_view`：公开路由首次显示、切换路由、刷新或从浏览器页面缓存恢复。查询参数改变不单独计数。
- `page_active`：页面在前台时每 30 秒及离开时尽力发送增量，单条最多 60 秒。后台标签页不累计。
- `bank_open`、`bank_loaded`、`bank_error`：题库开始载入、成功或失败。
- `question_preview`：预览 PDF 成功生成，不确认用户已经读完。
- `filter_apply`：分类筛选变化；不收集关键词搜索。
- `random_generated`：随机组卷成功生成选题。
- `export_started`、`export_success`、`export_error`：导出开始与结果。现有下载统计继续保存大小、生成时间和题数；这套访问统计只保存文件类别与结果。

## 数据与隐私

服务端使用白名单拒绝多余字段。只接收随机事件 ID、临时会话 ID、事件类别、允许的页面路径、语言、窗口类别、题库类别、文件类别和可见时长。服务端生成入库时间。不会把 IP、身份、搜索内容、题号、URL 查询参数或来源网址写入统计表。

临时编号存放于 `sessionStorage`，不使用 Cookie 或持久访客编号。连续 30 分钟没有统计事件后更换；关闭标签页通常清除。浏览器恢复或复制标签页可能影响去重。若存储不可用，编号只保留在页面内存。尊重 Do Not Track 和 Global Privacy Control。

90 天前的事件由现有每日定时任务清理。Cloudflare 等托管服务自身的网络日志不属于应用统计表。匿名事件可能被伪造或拦截，不用于审计、计费或推断个人行为。

浏览器请求不阻塞页面、预览和导出，4 秒后停止等待；失败不影响用户操作。生产站点以外的本地预览不发送事件。管理页面不采集访问事件。

## 发布与验证

本轮新增文件 `backend/migrations/0003-usage-events.sql`，只增加独立表和索引，不改动题目、草稿、登录会话或下载历史。发布顺序：

1. 先在已授权的 D1 数据库应用此迁移。迁移可重复运行。
2. 发布 Worker，确认 `/health` 返回正常、未登录读取 `/admin/api/usage` 返回 401。
3. 发布含 `SiteAnalytics` 和题库事件的前端。
4. 登录后台，查看真实事件与更新时间；不要用本地测试数据作为真实流量。

检查命令：`node scripts/test-usage-analytics.mjs`、`node scripts/test-admin.mjs`、`node scripts/test-github-auth.mjs`。测试覆盖隐私字段拒绝、大小与类型检查、跨来源限制、事件 ID 去重、真实 GitHub 会话权限判断、分母交集、时间窗口、90 天清理、DNT/GPC、会话到期、查询参数排除、网络失败与脚本语法。页面布局另需浏览器检查。
